# 端末の配布と管理

テーブル端末 (タブレット) とホール端末 (スマートフォン) を店に配り、専用端末として動かす方法。  
アプリの作り (専用端末の方式の見分け方、管理対象の構成の読み方) は [architecture.md](architecture.md#-6-専用端末) に書いた。

## 🧭 1. 方式

本番は外部の EMM (端末をまとめて管理する製品) で配る。  
自前の Device Owner (アプリ自身が端末を管理する方式) は、開発と EMM のない小さな店のために残している。

| | 外部の EMM | 自前の Device Owner |
| --- | --- | --- |
| Device Owner | EMM の管理アプリ | このアプリ |
| 端末の登録 | EMM が出す QR コードやゼロタッチで、まとめて登録する | 初期化した端末を USB でつなぎ、adb で 1 台ずつ登録する |
| 専用端末の設定 | EMM の管理画面 (キオスク) で決める | アプリが掛ける |
| 接続先 | 管理対象の構成で、すべての端末に配る | 端末ごとに入れる |
| 端末の登録 | 管理対象の構成で登録トークンを配り、端末が起動したときに自分で登録する | 端末ごとにペアリングコードを入れる |
| アプリの更新 | EMM から配る | 入れ替える手段が別に要る |
| USB デバッグ | EMM のポリシーで止める | 止めない (adb で調べたり外したりできるように) |

- Device Owner は端末に 1 つだけなので、端末ごとにどちらかにする。  
  アプリは起動したときと画面が前に出たときに方式を見分けて、動きを替える
- 自前の Device Owner を QR コードで登録する作りは持たない。  
  OS の保護の仕組みが、許可されていない管理アプリを登録の途中で止めるため (使うには許可の申請と審査が要る)
- スタッフの PIN は、どちらの方式でも管理画面の店舗の設定で決める (端末は起動のときに店舗の設定と一緒に受け取る)

## 📲 2. 外部の EMM で配る

1. アプリを EMM に登録する。  
   完全管理と専用端末の向けには APK を直接配れる EMM が多く、ほかに管理対象のアプリストアの非公開のアプリにする方法もある
2. 専用端末 (キオスク) のポリシーを作り、このアプリだけを動かす (ロックタスクを許し、ホームアプリにする)
3. 管理対象の構成で、接続先と登録トークン (管理画面で店舗と種類を決めて出す) を決める ([4. 管理対象の構成](#-4-管理対象の構成))
4. 端末を初期化し、EMM が出す QR コードかゼロタッチで登録する
5. 端末は起動したときに登録トークンで自分で登録し、起動の画面でテーブルの割り当てを待つ。  
   管理画面でテーブルを割り当てると、端末はしばらくして (30 秒ごとに確かめる) 待受になる。  
   ホール端末はテーブルを割り当てずに、そのまま席のタブになる

ポリシーで勧める設定:

| 設定 | 値 |
| --- | --- |
| USB デバッグ (開発者向けの設定) | 止める |
| ステータスバーとロック画面 | 出さない |
| OS の更新 | 夜間に入れる (営業中に再起動しないように) |
| 画面 | 充電中は点けたままにする |

- アプリを更新するときは、バージョンコード (csproj の `ApplicationVersion`) を上げる
- EMM によっては、アプリの版を上げると前の版に割り当てた管理対象の構成が引き継がれないので、新しい版にも割り当てる

## 🔧 3. 自前の Device Owner で配る

1. 端末を初期化し、アカウントを足さずに初期設定を終える
2. 開発者向けの設定で USB デバッグを有効にし、PC とつなぐ
3. Release の APK を入れる (`adb install`)
4. このアプリを Device Owner にする (`adb shell dpm set-device-owner tableorder.terminal.table/.AdminReceiver`。ホール端末は `tableorder.terminal.hall/.AdminReceiver`)
5. 再起動すると、アプリがホームとして起動し、ロックタスクに入る
6. 端末の設定 (初めて起動したときに出る。後からはテーブル端末のスタッフメニュー、ホール端末の端末の画面から開く) で接続先と、管理画面で出したペアリングコードを入れて登録する

- Release の Device Owner は外せない (外すときは端末を初期化する)

## 🧩 4. 管理対象の構成

EMM の管理画面で、このアプリに次の値を配れる (定義は `Platforms/Android/Resources/xml/app_restrictions.xml`)。

| キー | 種類 | 内容 |
| --- | --- | --- |
| `apiEndPoint` | 文字列 | 注文サーバの URL (http / https)。端末の設定より優先し、端末では変えられなくなる |
| `enrollmentToken` | 文字列 | 端末の登録トークン。登録していない端末が起動したときに、この値で自分で登録する |

- 空の値と正しくない値 (URL でない、空白を含む) は使わず、端末の設定を使う
- 値を替えると、アプリは知らせを受けて読み直す (画面が前に出たときにも読み直す)
- 配っている値は、端末の情報 (テーブル端末はスタッフメニュー、ホール端末は端末の画面) の EMM の設定に出る
- テーブルは管理画面で端末に割り当てる (端末では入れない)
- 接続先を替えると、端末は起動からやり直して新しい接続先で登録し直す (登録は接続先ごと)
