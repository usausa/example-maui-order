# 端末の配布と管理

テーブル端末 (タブレット) とホール端末 (スマートフォン) を店に配布し、専用端末として動かす方法。  
アプリの実装 (専用端末の方式の判別、管理対象の構成の読み方) は [architecture.md](architecture.md#-6-専用端末) を参照。

## 🧭 1. 方式

本番は外部の EMM (端末をまとめて管理する製品) で配布する。  
自前の Device Owner (アプリ自身が端末を管理する方式) は、開発と、EMM のない小さな店のために残している。

| | 外部の EMM | 自前の Device Owner |
| --- | --- | --- |
| Device Owner | EMM の管理アプリ | このアプリ |
| 管理への登録 | EMM が出す QR コードやゼロタッチで、まとめて登録する | 初期化した端末を USB でつなぎ、adb で 1 台ずつ登録する |
| 専用端末の設定 | EMM の管理画面 (キオスク) で決める | アプリが適用する |
| 接続先 | 管理対象の構成で、すべての端末に配信する | 端末ごとに入力する |
| 注文サーバへの登録 | 管理対象の構成で登録トークンを配信し、端末が起動したときに自分で登録する | 端末ごとにペアリングコードを入力する |
| アプリの更新 | EMM から配信する | 入れ替える手段が別に要る |
| USB デバッグ | EMM のポリシーで無効にする | 有効のまま (adb で確認したり外したりできるように) |

- Device Owner は端末に 1 つだけなので、端末ごとにどちらかの方式にする
- アプリは、起動したときとフォアグラウンドになったときに方式を判別して、動きを切り替える
- 自前の Device Owner の QR コードでの登録には対応しない。  
  OS の保護の仕組みが、許可されていない管理アプリを登録の途中で止めるため (使うには許可の申請と審査が要る)
- スタッフの PIN は、どちらの方式でも管理画面の店舗の設定で決める (端末は起動のときに店舗の設定と一緒に受け取る)

## 📲 2. 外部の EMM で配る

1. アプリを EMM に登録する。  
   完全管理と専用端末の向けには、APK を直接配布できる EMM が多い。  
   管理対象のアプリストアの非公開のアプリにする方法もある
2. 専用端末 (キオスク) のポリシーを作り、このアプリだけを動かす (ロックタスクを許可し、ホームアプリにする)
3. 管理対象の構成で、接続先と登録トークンを設定する ([4. 管理対象の構成](#-4-管理対象の構成))。  
   登録トークンは、管理画面で店舗と種類を決めて発行する
4. 端末を初期化し、EMM が出す QR コードかゼロタッチで登録する
5. 端末は起動したときに、登録トークンで自分で登録する
   - テーブル端末: 起動の画面でテーブルの割り当てを待つ。  
     管理画面でテーブルを割り当てると、しばらくして待受になる (30 秒ごとに確認する)
   - ホール端末: テーブルを割り当てずに、そのまま席のタブになる

ポリシーの推奨設定:

| 設定 | 値 |
| --- | --- |
| USB デバッグ (開発者向けの設定) | 無効にする |
| ステータスバーとロック画面 | 出さない |
| OS の更新 | 夜間にインストールする (営業中に再起動しないように) |
| 画面 | 充電中は点けたままにする |

- アプリを更新するときは、バージョンコード (csproj の `ApplicationVersion`) を上げる
- EMM によっては、アプリのバージョンを上げると、前のバージョンに割り当てた管理対象の構成が引き継がれない。  
  その場合は、新しいバージョンにも割り当てる

## 🔧 3. 自前の Device Owner で配る

1. 端末を初期化し、アカウントを追加せずに初期設定を終える
2. 開発者向けの設定で USB デバッグを有効にし、PC と接続する
3. Release の APK をインストールする (`adb install`)
4. このアプリを Device Owner にする (`adb shell dpm set-device-owner tableorder.terminal.table/.AdminReceiver`)。  
   ホール端末は `tableorder.terminal.hall/.AdminReceiver` を指定する
5. 再起動すると、アプリがホームとして起動し、ロックタスクに入る
6. 端末の設定で、接続先と、管理画面で発行したペアリングコードを入れて登録する。  
   端末の設定は、初めて起動したときに出る。  
   あとからは、テーブル端末はスタッフメニュー、ホール端末は端末の画面から開く

- Release の Device Owner は外せない (外すときは端末を初期化する)

## 🧩 4. 管理対象の構成

EMM の管理画面で、このアプリに次の値を配信できる (定義は `Platforms/Android/Resources/xml/app_restrictions.xml`)。

| キー | 型 | 内容 |
| --- | --- | --- |
| `apiEndPoint` | 文字列 | 注文サーバの URL (https。開発の Debug は http も可)。端末の設定より優先し、端末では変更できなくなる |
| `enrollmentToken` | 文字列 | 端末の登録トークン。登録していない端末が起動したときに、この値で自分で登録する |

- 空の値と正しくない値は使わず、端末の設定を使う。  
  正しくない値は、URL でない値、Release での http、空白を含む値
- EMM で値を変更すると、アプリは通知を受けて再読み込みする。  
  フォアグラウンドになったときにも再読み込みする
- 配信されている値は、端末の情報の「EMM の設定」に出る (テーブル端末はスタッフメニュー、ホール端末は端末の画面)
- テーブルは管理画面で端末に割り当てる (端末では入力しない)
- 接続先を変更すると、アプリは起動からやり直して、新しい接続先で再登録する (登録は接続先ごと)
