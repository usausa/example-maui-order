# 作っていない機能

作っていない機能と、決めたいことをまとめる。  
作るときは、計画 ([plan.md](plan.md)) の章を見直して段階を決めてから作り、作ったものは構成 ([architecture.md](architecture.md)) に移す。

## 🔗 外部の連携

本部の管理システム・POS とつなぐところ。  
このシステムの中で閉じないので、設計 ([計画の外部の連携](plan.md#-外部の連携)) だけを置いた。

| 項目 | 中身 |
| --- | --- |
| 外部のクライアント | client credentials のトークン、範囲 (`scope`)、管理画面での発行・秘密の出し直し・取り消し、取り消したクライアントのトークンをすぐに拒む |
| メニューと写真の公開 | 写真を置く API、メニューを丸ごと公開してすぐに反映、消えた品の品切れの片付け、`menu.published` |
| 端末の読み直し | テーブル端末・ホール端末・キッチン端末が `menu.published` ですぐに読み直し、カートの使えなくなった品を外して知らせる |
| POS | テーブル・来店・会計の明細の参照と、レジで払った来店の終了 |
| Webhook | 送り先の登録、署名、24 時間の送り直し、送り状況と手での送り直し |

## 🚀 本番の環境

AWS で動かすための構成と直すこと ([計画の本番の環境](plan.md#-本番の環境))。

| 項目 | 中身 |
| --- | --- |
| 構成 | Amazon ECS (AWS Fargate)、Amazon RDS、Amazon ElastiCache、AWS Secrets Manager、Application Load Balancer、AWS WAF、Amazon ECR、テレメトリ (Amazon CloudWatch、AWS X-Ray) |
| IaC | AWS CDK (C#)。環境 (開発、検証、本番、大きなテナントの専用の環境) を同じコードから作る |
| 複数台で動かす | トークンの要求の使い捨ての確かめと流量を全台で数える、データ保護の鍵の共有、管理画面のスティッキーセッション、デプロイの前のマイグレーション |
| データベース | PostgreSQL への移し替え (型、SQL、行のセキュリティ、接続のプール) |
| 専用の環境への移し替え | 大きなテナントを、共有の環境から専用の環境へ移す (テナントの行の移し替えと、端末の接続先の切り替え。運営者の画面から行う) |
| 画像の置き場 | Amazon S3 |

## 💳 決済

| 項目 | 中身 |
| --- | --- |
| 決済サービス | QR コード決済の事業者とカードの決済端末をつなぎ、本物の QR コードを作る。決済の結果の通知の署名を確かめる (今は開発の環境の仮の決済サービス) |
| 決済サービスの取り消し | 支払や会計をやめるときと、会計中の来店をレジで閉じるときに、決済サービスの支払も取り消す。やめた支払に届いた完了は捨てずに記録し、ホールに知らせる (今は注文サーバの支払の行を替えるだけ) |
| 決済サービスを呼ぶところ | 支払を作るときの決済サービスの呼び出しを、店舗の書き込みのロックの外に出す (待っている支払を書いてコミットしてから呼び、取引の番号と QR を書き足す。今は仮の決済サービスをロックの中で呼ぶ) |
| 失った支払の Id | テーブル端末が待っている支払の Id を失ったとき (起動し直しなど) は、その額をテーブルで払えない (QR は期限まで、カードはレジで閉じるまで)。待っている支払を会計の画面に出し、続けるか取り消せるようにする |

## 🏪 店舗のエッジ

| 項目 | 中身 |
| --- | --- |
| 回線が切れたとき | 回線が切れても店内で注文を回す (店舗に置くサーバ)。予備回線を置くかと合わせて決める |

## 🧩 そのほかの機能

| 項目 | 中身 |
| --- | --- |
| 電子レシートの画面 | 今は電子レシートの URL だけを返す |
| キッズメニューの数の上限 | キッズの品を子どもの人数までに限る (今は子どもがいれば数を限らない) |
| 割り当てをすぐに知らせる | 置き場所の割り当てを待つ端末は、今は起動の画面の 30 秒ごとの確かめ直しで割り当てを受け取る |
| OS のプッシュでの呼び出しの知らせ | ホール端末の画面が消えている間の呼び出しを、OS のプッシュの仕組みで届ける (今は前景サービスで通知の接続を保つ。外のサービスを通るので、端末の管理と合わせて決める) |
| 自前の Device Owner の QR コードでの登録 | 許可の申請が要る |
| 管理画面の外部の ID 基盤と操作の記録 | OIDC でのサインインと、監査ログ |
| 古いデータの片付け | 閉じた来店 (来店と、その確認の記録・注文・明細・チケット・呼び出し・支払・電子レシート) をサーバの設定の日数 (90 日など) で、メニューの公開を今のものと直近の 10 件を残して、Webhook の送り状況を 7 日で、解約したテナントのすべての行を解約からサーバの設定の日数で消す。売上の正は POS なので、閉じた来店は Webhook で渡したあと、問い合わせと集計に使う間だけ残す (今は通知と登録の受け口だけを消す) |

## ❓ 決めたいこと

- 待受で言語を選ばせるか (今は待受と注文の画面のヘッダのボタンから選ぶ)
- 決済サービス (QR コード決済の事業者、カードの決済端末をテーブル端末につなぐか)
- 電子レシートの要否
- 子どもの区分 (今は小学生以下)
- 予備回線の要否 (店舗のエッジを置くかと合わせて)
- RDS のエンジン (PostgreSQL か Aurora PostgreSQL か) と、IaC のプロジェクトの置き場所 (新しい区分 `infra/` か)
