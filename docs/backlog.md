# 作っていない機能

作っていない機能と、決めたいことをまとめる。  
店舗の中で閉じない機能と環境 (外部の連携、本番の環境、決済、店舗のエッジ) は、設計と決めたいことだけを置き、今は作らない。  
作るときは、計画 ([plan.md](plan.md)) の章を見直して段階を決めてから作る。  
作ったものは構成 ([architecture.md](architecture.md)) に移す。

## 🔗 外部の連携

本部の管理システム・POS との連携。  
このシステムの中で閉じないので、設計 ([計画の外部の連携](plan.md#-外部の連携)) だけを置いた。

| 項目 | 中身 |
| --- | --- |
| 外部のクライアント | client credentials のトークンと範囲 (`scope`) |
| メニューと写真の公開 | 写真をアップロードする API と、メニューの公開 |
| 端末の再読み込み | テーブル端末・ホール端末・キッチン端末が、`menu.published` ですぐに再読み込みする |
| POS | テーブル・来店・会計の明細の参照と、レジで払った来店の終了 |
| Webhook | 送り先の登録、署名、24 時間の再送、配信状況と手動の再送 |

- 外部のクライアント: 管理画面で発行・シークレットの再発行・取り消しをする。  
  取り消したクライアントのトークンは、すぐに拒否する
- メニューと写真の公開: メニューを丸ごと公開し、すぐに反映する。  
  公開で消えた品の品切れを削除し、`menu.published` を送る
- 端末の再読み込み: カートの使えなくなった品は外して、メッセージを出す

## 🚀 本番の環境

AWS で動かすための構成と、直すこと ([計画の本番の環境](plan.md#-本番の環境))。  
次のこともここで決める。

- RDS のエンジン: PostgreSQL か Aurora PostgreSQL か
- IaC のプロジェクトの置き場所: 新しい区分 `infra/` か

| 項目 | 中身 |
| --- | --- |
| 構成 | Amazon ECS (AWS Fargate)、Amazon RDS、Amazon ElastiCache、AWS Secrets Manager、Application Load Balancer、AWS WAF、Amazon ECR、テレメトリ (Amazon CloudWatch、AWS X-Ray) |
| IaC | AWS CDK (C#)。環境 (開発、検証、本番、大きなテナントの専用の環境) を同じコードから作る |
| 複数台で動かす | 全台で共有する状態、管理画面のセッション、マイグレーションの流し方を直す |
| データベース | PostgreSQL への移行 (型、SQL、行レベルセキュリティ、コネクションプール) |
| 専用の環境への移行 | 大きなテナントを、共有の環境から専用の環境へ移す |
| 画像の保存先 | Amazon S3 |
| クラッシュレポートの収集 | 端末のクラッシュレポートを集めるサービスにつなぐ |

- 複数台で動かす
  - トークンのリクエストのリプレイ防止と、レート制限を全台で数える
  - データ保護の鍵を共有する
  - 管理画面はスティッキーセッションにする
  - マイグレーションはデプロイの前に流す
- 専用の環境への移行: テナントの行を移し、端末の接続先を切り替える。  
  運営者の画面から行う
- クラッシュレポートの収集: 今は端末の中に残し、次の起動でログに書く。  
  サーバや外のサービスには送らない

## 💳 決済

決済サービスはこのシステムの外の契約と環境なので、決めるところから保留している。  
決めること:

- QR コード決済の事業者
- カードの決済端末をテーブル端末につなぐか

| 項目 | 中身 |
| --- | --- |
| 決済サービス | QR コード決済の事業者とカードの決済端末につなぎ、本物の QR コードを作る (今は開発の環境の仮の決済サービス) |
| 決済サービスの取り消し | 決済サービスの支払も取り消す (今は注文サーバの支払の行を変更するだけ) |
| 決済サービスの呼び出し | 支払を作るときの決済サービスの呼び出しを、店舗の書き込みのロックの外に出す (今は仮の決済サービスをロックの中で呼ぶ) |
| 失った支払の Id | 待っている支払を会計の画面に出し、続けるか取り消せるようにする |

- 決済サービス: 決済の結果の通知の署名を検証する
- 決済サービスの取り消し: 支払や会計をやめるときと、会計中の来店をレジで閉じるときに取り消す。  
  やめた支払に届いた完了は、捨てずに記録してホールに通知する
- 決済サービスの呼び出し: 待っている支払を書いてコミットしてから呼び、取引の番号と QR を書き足す
- 失った支払の Id: 今は、テーブル端末が待っている支払の Id を失うと (起動し直しなど)、その額をテーブルで払えない。  
  払えない期間は、QR は期限まで、カードはレジで閉じるまで

## 🏪 店舗のエッジ

店舗の環境として、回線が切れたときの扱いと予備回線の要否を一緒に決める。

| 項目 | 中身 |
| --- | --- |
| 回線が切れたとき | 店舗に置くサーバで、回線が切れても店内で注文を回す |

## 🧩 そのほかの機能

| 項目 | 中身 |
| --- | --- |
| キッズメニューの数の上限 | キッズの品を子どもの人数までに限る (今は子どもがいれば数を限らない) |
| 割り当てをすぐに通知する | 置き場所の割り当てを待つ端末に、すぐに届ける (今は起動の画面が 30 秒ごとに再確認して受け取る) |
| OS のプッシュ通知での呼び出し | ホール端末の画面が消えている間の呼び出しを、OS のプッシュ通知で届ける (今はフォアグラウンドサービスで通知の接続を保つ) |
| 自前の Device Owner の QR コードでの登録 | 許可の申請が要る |
| 管理画面の外部の ID プロバイダと監査ログ | OIDC でのサインインと、監査ログ |
| 待受での言語の選び方 | 待受で言語を選ばせる (今は待受と注文の画面のヘッダのボタンから選ぶ) |
| 子どもの区分 | 子どもとして数える区分を決める (今は小学生以下) |
| 解約したテナントのデータの削除 | 解約したテナントのすべての行と画像を、解約からサーバの設定の日数で削除する |

- OS のプッシュ通知での呼び出し: 外のサービスを通るので、端末の管理と合わせて決める
- 解約したテナントのデータの削除: テナントの解約の操作と一緒に作る。  
  閉じた来店とメニューの公開は、保持期間で削除している
