# API クライアント (TableOrder.Client)

## 構成

- API クライアントは、端末の種類ごと (`ITableApi` など) と、すべての端末に共通の `IDeviceApi` (登録、トークン、状態の報告、端末の設定) に分ける
- 通知の受信は `IOrderEvents` にする
- 注文サーバの実装は名前の前に通信の方式を付け、REST の API クライアントは端末の種類ごと (`RestDeviceApi`、`Rest{種類}Api`) に分ける
- リクエストの送り方 (接続先、トークンの再取得、タイムアウト、結果の分類) は `RestConnection` にまとめる
- 複数の端末の種類の API クライアントが同じ手順で読むもの (メニューの `304` での使い回し) は、共通の部品 (`RestMenuCache`) にして各 API クライアントが持ち、API クライアントごとに書かない
- 画像は `IDeviceApi.GetImageAsync` で中身をそのまま受け取り、保存と使い回しは端末に任せる
- JSON はソース生成の `ClientJsonContext` で読み書きする (端末のトリミングでリフレクションの型の情報が消えるため)
- 通信データと通知の中身の型を足したら、`[JsonSerializable]` にも足す

## 結果と失敗

- 結果は `ApiResult<T>` で返し、例外を投げない
- 内容のないレスポンスは `NoContent` にする
- 失敗は、4xx を `Rejected` (`errorCode` と文言を読む)、401 を `Unauthorized`、5xx・408・429・タイムアウト・通信できないを `Unavailable`、呼び出し元の取り消しを `Canceled` にする
- 通信の部品が投げる例外 (`HttpRequestException`、Android の通信の `WebException`、`IOException` など) は `Unavailable` にして返し、API クライアントの外に出さない (タイムアウトで閉じた接続でも投げられ、コマンドの外まで抜けるとアプリが落ちる)

## 端末の値とトークン

- 端末の側の値 (接続先、登録した端末の ID、端末の鍵) は `IDeviceContext` で受け、実装が端末の設定を直接読まない
- 接続先と端末の ID はリクエストのたびに `IDeviceContext` から読み、端末の設定で変更しても API クライアントを作り直さない
- アクセストークンは API クライアントの中で持ち、画面に渡さない
- トークンのリクエストが拒否されたら (無効化、テナントの停止) `Denied` で端末の ID と理由を、受け取れたら `Authorized` で端末の ID を通知する
- テナントの停止で拒否されたら、起動でのトークンの再取得 (`AuthenticateAsync`) がトークンを受け取るまで、ほかのリクエストはトークンを求めずに同じ拒否を返し、`Denied` も出さない (停止の間にリクエストを送り続けない)

## 端末の鍵

- 端末の鍵の値は `DeviceCredentials` で API の形 (JWK、ES256 の JWT) に変換し、変換には .NET の ASN.1 の読み書きを使う (端末の暗号の実装に頼らない)
- 端末の鍵 (`IDeviceKey`) の公開鍵と署名は非同期にする (ブラウザの鍵は非同期でしか使えない)
- 時間のかかる鍵の操作は、鍵の実装が UI スレッドの外で行う
- 署名は DER で返し、ほかの形を返す鍵 (WebCrypto の r と s を並べた形) は `DeviceCredentials.ToDerSignature` で DER に変換する
- 端末の鍵 (`IDeviceKey`) の失敗 (鍵がない、Keystore や WebCrypto の失敗) は `CryptographicException` だけを投げ、API クライアントは通信できない (`Unavailable`) として返す (再接続と状態の報告を例外で止めない)

## 通知

- 通知は、端末が今の状態を読む前に `ConnectAsync` で接続し、`ready` の番号から数える
- 再接続したら欠落した通知を読み、その間に届いた通知と合わせて seq の順に渡す
- 再接続では切れたとき (`Reconnecting`、閉じて始め直すとき) から通知をため、`ready` より前に届いた通知で番号を進めない (ハブはグループに入れてから番号を読むので、先に届いた通知で番号を進めると欠落した通知を読み飛ばす)
- 再接続が重なったら、最後に始めた欠落した通知の読み込みだけを使う
- 通知には接続 (`OrderEventArgs.Connection`) を付け、`ConnectAsync` で作り直したら前の接続の通知と読み込みは渡さない
- 通知の数え方は、通信に依らない部品 (`EventSequencer`) に分けてテストする
- 扱わない種類の通知と読めない中身は渡さずに seq だけを進める (欠落と取り違えない)
- 通知の型 (`OrderEvent`) には端末が使う中身だけを持たせる (使わない中身は、共有の型を調べるソリューションの InspectCode が使われていないと指摘する)
- 端末が一覧を再取得する通知 (呼び出し、チケット) は中身を持たない
- 通知の配信 (`SignalROrderEvents.DispatchAsync`) はレシーバの例外をすべて捕まえて配信を続け、渡しそこねた通知の代わりに `Expired` で今の状態を再取得させる (止まると以後の通知がどの画面にも届かない)
- CA1031 の抑止は、通知の配信でレシーバの例外を捕まえる 1 か所だけにする
- ハブに接続する前のネゴシエーション (negotiate) にはタイムアウトを付ける (サーバに届かないときに再接続を止めない)
- 再接続が 401 で拒否されたら、トークンを再取得する (署名の鍵が変わったときに再接続を止めない)
- 通知の再接続は、トークンを取得できない間は接続前のネゴシエーションも送らない (テナントの停止の間にリクエストを送り続けない)
