# 端末の部品と状態

## 共通の部品

- 端末のアプリに共通の部品 (端末の部品、端末の設定と状態、スタッフの PIN、登録と状態の報告、通知のレシーバの基底クラス) と、お客様の画面の端末に共通の部品 (チェーンの色、画像の保存、チェーンの印、言語) は `TableOrder.Terminal` に置く
- アプリには、画面とそのアプリだけが使うものを置く
- どの端末のアプリでも同じもの (起動の準備 `StartupState`、ビジーオーバーレイ `ShellProperty`、長押しの時間 `AppGestures`) は、アプリごとにコピーせずに `TableOrder.Terminal` に置く
- メニューの出し分け (出せる条件のルール) は `TableOrder.Terminal` の `MenuAvailability` で判定し (時刻は店舗の現地時刻、人数は来店の子ども)、アプリごとに判定をコピーしない
- 使わない部品 (フォーカスの移動、入力のフィルタ、角丸、選択の添付プロパティ、使わない端末の値) を共通の部品に残さない (規則に反する部品を新しい画面が使えないように)
- 共通の部品は `AddTerminalComponents` で登録し、お客様の画面の部品はお客様が触る端末 (テーブル端末、受付機) だけが `AddCustomerComponents` で登録する
- ソース生成の DI がファクトリを作れるように、共通の部品の型をアプリの `GeneratedFactory` に足す
- 共通の部品からアプリの型を参照しない
- アプリごとに違う Android の型 (Device Owner のレシーバ `AdminReceiver`、ホームにする画面 `MainActivity`) は、アプリが `KioskOptions` で渡す
- 共通の部品にアプリの端末の種類を書かない
- 登録で送る端末の種類は、アプリが `TerminalOptions` で渡す (違う種類のコードはサーバが拒否する)
- 共通の部品の基底クラスでアプリが決める処理は abstract にし、使わないアプリは何もしない実装を理由のコメントと一緒に書く (virtual の既定にすると、使わないアプリのソリューションの InspectCode がオーバーライドされていないと指摘する)
- 言語は `LanguageState` で切り替え (`TerminalResources` のカルチャも切り替わる)、アプリの文言のカルチャを切り替える処理は `LanguageOptions` で渡す

## 通知

- 通知のレシーバは `OrderEventReceiverBase` を継承し、届いたときにすぐ行う処理 (`OnReceived`)、通知の扱い (`ApplyAsync`)、待っていた通知を扱い終えたときの処理 (`OnDrainedAsync`)、起動からやり直すイベント (`NotifyRestartAsync`) をアプリで決める
- 届いたらすぐに知らせる処理 (新しい呼び出しの音と振動) は `OnReceived` で行う (`ApplyAsync` と `OnDrainedAsync` は、操作の途中とポップアップを開いている間は待たされる)
- 通知の重複は接続 (`OrderEventArgs.Connection`) ごとに seq で捨て、接続が変わったら数え直す (端末の ID では数え直さない。再登録しても、再接続するまでは前の接続の通知が届く)
- 起動からやり直すイベントを受けない画面 (起動、端末の設定) は `AcceptsRestart` で示す
- `AcceptsRestart` が false の間は、印を残して受ける画面に移ってからイベントを出し、ポップアップを閉じない (テナントの停止の拒否が繰り返し届いても、PIN や登録の入力を閉じない)
- 拒否 (`Denied`) による起動からのやり直しは、ほかの理由のやり直しと別の印に残し、そのあとにトークンを受け取れたら (`Authorized`。起動の画面で回復したら) 下ろす (起動の画面は自分のトークンの再取得の拒否を自分で扱うので、回復して受ける画面に移ったときに、もう一度起動からやり直さない)
- サーバの通知は `OrderEventReceiver` が受けて状態を更新し、操作の途中と遷移の間を待ってから `ShellEvent` で表示中の画面に伝える
- 通知での画面の動きは各画面が `OnVisitOpenedAsync` などで決め、レシーバから画面を動かさない
- 端末が使えなくなったとき (無効化、テナントの停止)、管理画面で端末を変更したとき (`device.updated`)、EMM が接続先を変更したとき、通知を追跡できなくなったとき (`Expired`) は、`OrderEventReceiver` が `ShellEvent.Restart` を出し、表示中の画面が起動からやり直す (基底クラスの `OnRestartAsync`。起動と端末の設定の画面は自分で確認するので受けない)

## 一覧の再取得

- 通知を受けて一覧を再取得するときは、通知ごとに再取得せず、届いたとき (`OnReceived`) に再取得の印を付け、`OnDrainedAsync` (待っていた通知を扱い終えたとき) でまとめて再取得する
- 再取得の印は、その一覧の中身を変えるすべての通知で付ける (提供は `order.created` でも変わる。持ち場のない品は注文を受けたときにできあがる)
- 再取得の印は再取得の前に下ろし、再取得できなかったら戻す (再取得を待つ間に届いた通知の印を、再取得のあとの代入で消さない)
- 印を戻すときは、結果を待ってから印を読む (`var ok = await ...; x |= !ok;`。`x = !await ...` は待つ間に付いた印を上書きし、`x |= !await ...` は待つ前の値で書く)
- 次の通知を待てない一覧 (受付機の空席) は、再取得できなかった印を State に残し、画面がしばらくごとに再取得する

## 送信と再送

- 新しく作るリクエスト (案内、注文) は、送れたかわからない (`Unavailable`) ときに ID を残し、再送では同じ ID を使う (サーバは同じ ID の再送に受けたものを返し、内容が違えば `DUPLICATE_ID_MISMATCH` で拒否する)
- 送れたときと拒否されたときは、ID を残さない
- 残した ID は同じお客様が再送するときだけ使い、お客様が変わるとき (受付機は人数の画面に入るとき) に捨てる
- 再送で返った来店が開いていなければ、使わずに新しく作る (サーバは同じ ID の再送に、来店の状態を問わず受けたものを返す)
- 残した ID で再送するのは同じ内容 (案内はテーブルと人数、代わりの注文はカート) のときだけにし、内容を変えたら新しい ID にする (サーバは同じ ID の再送に、内容を見ずに受けたものを返すか、違う内容として拒否する)
- 送れたかわからない注文 (カートの `PendingOrderId`) があるうちは、カートを直させずに同じ内容で再送させる (直すと、届いていた注文と二重になるか、同じ ID の違う内容として拒否される)
- 送れたかわからない注文と同じ ID の `order.created` を受けたら、送れたものとしてカートを空にし、受け付けたことを表示する
- 支払は、作るリクエストの結果がわからない間と取り消しが通らない間も、ID、方法、額を残す
- 残した支払と同じ方法と額で払うときは、同じ ID で再送する
- ほかの払い方にするときは、残した支払を先に取り消す (取り消す前に払い終わっていたら、払い終えたものとして進める)
- 期限のある支払 (QR) は、期限を過ぎたら取り消して支払方法の選び直しに戻す (使えない QR を出したまま待たない)
- 割り勘の 1 人分を払い終えたら、その時点で割る人数を減らし、明細を再取得できるまでリトライしてから支払方法の選び直しに戻す

## 状態と Usecase

- State と Usecase は画面の書式 (`ViewHelper`) を使わず、サーバの文字は `LocalizedText` のまま返す (言語で選ぶのと文言の組み立ては ViewModel で行う)
- テーブルの名前は端末の設定 (`MenuState.TableName`) から出し、端末の側にテーブルを持たない
- 店舗の設定で変わる動き (機能の有無 `MenuState.Features`、支払方法、呼び出しの用件、明細の上限) は設定から読み、端末に固定の値を持たない
- カートに入れる前の上限 (1 回の注文の明細の数、同じ内容の行にまとめた 1 明細の数量、メニューのルールの上限、商品とオプションの残りの数) は `OrderUsecase.FindExceededLimit` で確認し、注文の画面と提案の追加で同じ確認を通す
- テーブル端末の来店が終わったか (閉じた、取りやめた、ほかのテーブルに移った) は `VisitState.IsFinished` で見る (状態の `Closed` だけで見ない。移った来店の状態は `Open` のまま届く)
- テーブル端末は、来店が終わってから画面が来店を終えるまで (お礼の間、スタッフメニューの間) に同じテーブルで開いた次の来店 (移ってきた来店も) を `VisitState.Next` に残し、来店を終えたら続けて開いて注文の画面にする (通知を捨てると、次のお客様の来店が待受のまま止まる)

## クラッシュレポート

- 前回の異常終了はお客様の画面に出さず、起動を待たせずに、次の起動でログに残す (`CrashReport.LogPrevious`)
- 観測されなかったタスクの例外はクラッシュレポートに記録せず、ログにだけ残す (`CrashReport.WatchUnobserved`)

## Android

- Android の API は `Components/` の部品にまとめ (共通の部分は `Xxx.cs`、Android の部分は `Xxx.android.cs`)、画面と状態から直接呼ばない
- Android だけのクラスは `Platforms/Android/` の下の用途のフォルダ (`DirectFontImageSourceService` は `Graphics/`) に置き、直下には Android のエントリポイント (`MainActivity`、`MainApplication`) と `AndroidHelper` だけを置く
- 端末で鳴らす音は端末の通知音にし、通知の音量で鳴らす (`Ringtone` の `AudioAttributes` を通知にする。既定は着信の音量)
- 振動は `GetSystemService(Class)` で `Vibrator` を取得する (名前で取得する `Context.VibratorService` は Android 12 で廃止され、警告になる)
- 振動には用途を付ける (Android 13 以降は `VibrationAttributes`、それより前は `AudioAttributes`。用途のない振動は、バックグラウンドの間は捨てられることがある)
- 画面が消えている間もすぐに知らせる処理 (ホール端末の新しい呼び出し) は、フォアグラウンドサービス (`specialUse`) と部分ウェイクロックで、アプリと通知の接続を動かし続けて行う
- フォアグラウンドサービスは、画面がフォアグラウンドになったときに始める (バックグラウンドからは始められない)

## 専用端末と管理対象の構成

- 管理対象の構成 (EMM が配信する設定) は `Components/ManagedConfiguration` で読み、`Settings` が端末の設定より優先して返す
- 配信された値で端末の値を書き換えない (配信されなくなったら端末の値に戻る)
- 管理対象の構成のキーを足すときは、`Platforms/Android/Resources/xml/app_restrictions.xml`、名前と説明の文言 (`values` / `values-en` の `restrictions.xml`)、`ManagedConfiguration` を揃える
- 配信された値のうち、空の値は配信されていないものとして扱い、正しくない値は使わずに記録する (どちらも端末の設定を使う)
- 管理対象の構成の変更の通知 (`ACTION_APPLICATION_RESTRICTIONS_CHANGED`) は動いている間に登録したレシーバにだけ届くので、画面がフォアグラウンドになったときにも再読み込みする
- 専用端末の方式 (Device Owner、EMM の許したロックタスク) は動いている間に変わることがあるので、画面がフォアグラウンドになったときに適用し直し、スタッフメニューに出すときにも判定し直す
- 全画面と専用端末 (ロックタスク、Device Owner の制限、一時的な解除) は `Components/KioskManager` にまとめ、画面から直接 Android の API を呼ばない

## 登録と鍵

- 端末の鍵は `Components/DeviceKey` (Android の Keystore の P-256) に作り、秘密鍵を取り出さない
- 鍵の値は Keystore の形 (公開鍵は SubjectPublicKeyInfo、署名は DER) のまま返す
- 鍵は再登録しても使い回し、端末を無効にされたときだけ削除する (登録に失敗しても前の登録を壊さない)
- 登録した端末の ID は登録した接続先と組で `Settings` に持ち、今の接続先と違えば登録していないものとする (接続先ごとに登録する)
- 登録は送った接続先の登録として覚え、送る間に接続先が変わったら覚えない
- 接続先の形式は `ApiEndPoints.IsValid` で検証し、端末の設定と EMM の構成で同じ検証を使う (Release は平文の通信を止めているので https だけ)
- EMM の登録トークンは、登録していない端末が起動したときだけ使う (登録している端末は再登録しない)
- 無効にされた端末は、EMM の登録トークンが残っていても自分では再登録しない (`Settings.IsRevoked`。端末の設定で再登録する)

## 画像

- 画像 (料理の写真、チェーンのロゴ) は `ImageCache` (`TableOrder.Terminal`) が登録ごとのフォルダに名前で保存し、保存したものは再取得しない (名前は内容が変わると変わる)
- 画像の名前は、保存の前に `ImageNames.IsValid` で検証する
- 画像は起動のときにまとめてダウンロードし (同時に 4 つまで。タイムアウトを付ける)、ダウンロードできなくても起動を止めない
- ダウンロードできなかった画像は、待受に戻ったときに再取得する
- 今のメニューで使わない画像とほかの登録のフォルダは、ダウンロードのときに削除する

## スタッフの PIN

- スタッフの PIN は、店舗の設定のハッシュ (`StaffPinHash`) を登録と一緒に `Settings` に保存し、平文の PIN を持たない (EMM でも配信しない)
- 登録を削除するときに、PIN のハッシュも削除する
- PIN の確認 (回数の多い計算) は UI スレッドの外で行う
- PIN は `StaffLock` で検証し (店舗の設定のハッシュ、間違いが続いたら止める)、起動に失敗したときの端末の設定にも同じ検証を使う
